# Задача: редактирование и удаление медиафайлов

Используй инструкции проекта из `.github/copilot-instructions.md` и техническое задание Media Storage.

## Задача

Реализуй возможность редактировать название и удалять изображения, видео и аудиофайлы.

Перед изменениями изучи текущую структуру проекта, связанные компоненты, типы и API. Учитывай фактическое состояние приложения и используй уже существующую интеграцию с Supabase.

### 1. Редактирование названия
- Добавь действие редактирования названия выбранного файла.
- Используй диалог MUI с текущим названием, полем ввода и кнопками «Сохранить» и «Отмена».
- Запрещай сохранение пустого названия.
- Сохраняй изменения в `media_items.title` через существующий API-слой.
- Синхронизируй название в библиотеке, панели выбранного файла и окне просмотра без перезагрузки страницы.

### 2. Удаление файла
- Добавь действие удаления с обязательным подтверждением.
- Удаляй файл из приватного Supabase Storage bucket `media-files` и соответствующую запись из `media_items`.
- Корректно обрабатывай `file_path` и `preview_path`, не удаляя один объект дважды.
- После успешного удаления убирай файл из библиотеки, сбрасывай выбор и закрывай окно просмотра, если в нём открыт удалённый файл.
- Обрабатывай ошибки Storage и БД, включая частичное выполнение операции. Не показывай успех, если удаление завершилось не полностью.

### 3. Общие требования
- Используй существующие Supabase client, API-слой и механизмы обновления состояния.
- Учитывай авторизацию и RLS. Не обходи политики доступа и не используй `service_role` key на frontend.
- Показывай ошибки пользователю и блокируй повторное выполнение действий во время запросов.
- Сохрани существующий дизайн, адаптивность и остальные функции приложения.
- Вноси минимальные изменения, не выполняй посторонний рефакторинг и не добавляй новые библиотеки без необходимости.

### 4. Проверка
Проверь переименование, валидацию названия, отмену операций, удаление файлов всех трёх типов, обновление интерфейса и обработку ошибок. Запусти `npm run build` из каталога `frontend` и другие доступные релевантные проверки.

В конце перечисли изменённые файлы, реализованные функции, результаты проверок и оставшиеся проблемы. Указывай только фактически выполненные изменения.

Важно: если код проекта противоречит отдельным пунктам инструкций о работе только с mock-данными, ориентируйся на существующую интеграцию Supabase для этой задачи, не расширяя область работ.
