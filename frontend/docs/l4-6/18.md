# ДЗ — Документирование Backend и интеграции с Frontend

## Role — Роль

Ты — опытный разработчик React, TypeScript и Supabase, отвечающий за техническую документацию веб-приложения.

## Context — Контекст проекта

Проект **Media Storage** — веб-приложение для хранения и управления изображениями, видео и аудиофайлами.

Технологический стек:
- Frontend: React, TypeScript, Vite, Material UI.
- Backend-as-a-Service: Supabase.
- База данных: PostgreSQL в Supabase.
- Авторизация: Supabase Auth.
- Файловое хранилище: Supabase Storage.
- Доступ к данным: Supabase JavaScript Client.
- Контроль доступа: Row Level Security (RLS).

Предполагаемая функциональность включает регистрацию и авторизацию, просмотр медиатеки, загрузку и удаление файлов, переименование медиа, работу с коллекциями и отображение информации о занятом хранилище.

Этот список необходимо проверить по исходному коду. Не описывай как реализованные функции, которые фактически отсутствуют или работают иначе.

## Task — Задача

Изучи существующий проект и подготовь техническую документацию Backend и интеграции с Frontend.

Создай или обнови следующие файлы:

1. `backend_documentation.md` — основная документация backend.

4. SQL-файл миграции, если его ещё нет в проекте и структуру БД можно достоверно восстановить из имеющихся SQL-файлов, конфигурации и кода.

Сначала проверь существующие файлы и документацию. Не перезаписывай полезную информацию без необходимости и сохраняй принятую в проекте структуру каталогов.

# Media Storage

Media Storage — это frontend-приложение для просмотра и организации домашней медиатеки. Оно предназначено для работы с изображениями, видео и аудиофайлами, а также для создания подборок (коллекций) из пользовательских файлов.

На текущем этапе проект представляет собой frontend-MVP: данные загружаются из mock-объектов, вся логика хранится в React-состоянии, а серверная часть ещё не подключена.

## Статус проекта

Реализовано:

- главная библиотека с карточками медиафайлов;
- поиск по названию и фильтрация по типу файла;
- просмотр файла в модальном окне с навигацией по предыдущему/следующему элементу;
- управление коллекциями: создание, добавление файлов, удаление из коллекции, удаление коллекции;
- загрузка файлов с клиентской валидацией формата и размера;
- адаптивный интерфейс на базе Material UI;
- базовые автоматические тесты на пользовательские сценарии.

Не реализовано на сервере:

- реальная загрузка файлов;
- хранение данных на backend;
- авторизация и пользователи;
- синхронизация между устройствами;
- постоянное хранение коллекций и метаданных.

## Основные функции и сценарии

### 1. Медиатека

- просмотр всех медиафайлов в единой библиотеке;
- отдельные разделы для изображений, видео и аудио;
- поиск по названию файла;
- фильтрация по типу: все, фото, видео, аудио;
- пустое состояние при отсутствии результатов поиска.

### 2. Просмотр медиафайла

- открытие выбранного файла в полноэкранном модальном окне;
- отображение заголовка, типа, размера и метаданных;
- навигация между файлами внутри текущего отфильтрованного набора;
- закрытие по клавише Escape и кнопке.

### 3. Коллекции

- создание коллекций с названием и описанием;
- добавление файлов в коллекцию из доступного списка;
- удаление файла из коллекции;
- удаление самой коллекции с подтверждением;
- хранение состояния локально в памяти приложения.

### 4. Загрузка файлов

- выбор файлов через диалог браузера;
- проверка типа файла и лимита размера;
- отображение очереди файлов и статусов загрузки;
- уведомления об ошибках и успешной загрузке в заглушку;
- валидация без отправки данных на сервер.

## Архитектура frontend

Проект структурирован по слоям:

- `src/App.tsx` — корневой экран приложения и маршрутизация;

- `src/components/` — общие UI-компоненты;
- `src/features/` — бизнес-логика и hooks;
- `src/entities/` — слой работы с mock API;

- `src/types/` — типы данных приложения;

## Серверные endpoint, которые нужно реализовать

Ниже — минимальный набор endpoint, необходимых для перехода от mock-frontend к полноценному backend.

### 1. Медиа

- `GET /api/media` — получить список всех медиафайлов
- `GET /api/media?type=image` — получить медиа по типу
- `GET /api/media?query=лес` — поиск по названию
- `GET /api/media/:id` — получить конкретный файл
- `POST /api/media/upload` — загрузить новый файл
- `DELETE /api/media/:id` — удалить медиафайл

### 2. Коллекции

- `GET /api/collections` — получить все коллекции пользователя
- `POST /api/collections` — создать коллекцию
- `GET /api/collections/:id` — получить коллекцию по ID
- `DELETE /api/collections/:id` — удалить коллекцию
- `POST /api/collections/:id/items` — добавить файл в коллекцию
- `DELETE /api/collections/:id/items/:mediaId` — удалить файл из коллекции

### 3. Хранилище и статистика

- `GET /api/storage/summary` — получить объём использованного и свободного места
- `GET /api/library/summary` — получить сводку по библиотеке

### 4. Загрузка и валидация файлов

- `POST /api/uploads/validate` — проверить тип, размер и корректность файла
- `POST /api/uploads` — создать запись о загруженном файле
- `GET /api/uploads/:id/status` — получить статус загрузки

### 5. Поиск и фильтрация

- `GET /api/search?q=...` — универсальный поиск по медиатеке
- `GET /api/media/filters` — получить доступные типы файлов
