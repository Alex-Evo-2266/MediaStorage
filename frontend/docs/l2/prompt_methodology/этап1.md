## 🔎 Какие факты были использованы при принятии решения

Основано на текущей реализации:

- В MediaTagger/src/main/GaleryStore.ts уже есть источник списка тегов: `tagIndex` и `getAllTags()`
- Индексация тегов уже выполняется через `buildIndexes()`
- Поиск и фильтрация по тегам уже использует `this.tagIndex.get(tag.toLowerCase())` в `search(filter)`
- В UI сейчас нет нормализации и нет автоподсказок; добавление идёт через `!tags.includes(...)` в компонентах:
  - MediaTagger/src/renderer/src/components/Gallery.tsx
  - MediaTagger/src/renderer/src/components/GalleryWithGroup.tsx
  - MediaTagger/src/renderer/src/components/ImageDialog.tsx
  - MediaTagger/src/renderer/src/components/ImageDialogWithGroup.tsx

Это подтверждает, что правильная точка расширения — backend + IPC, а не UI-логика.

## 🧠 Что было принято в решении

1. Нормализация делается в основном слое, а не в renderer.
   - Причина: это уже соответствует архитектуре проекта и закрывает все точки ввода тегов одним местом.
2. Для автоподсказок добавлен базовый метод `getTagSuggestions(term, limit)`.
   - Он работает по существующему списку `getAllTags()` и фильтрует по вхождению строки в нижнем регистре.
3. При сохранении тегов добавлена нормализация `trim + collapse spaces + lower-case`.
   - Это защищает от дублей вида `forest`, ` Forest `, `forest `.

## ⚠️ Что ещё остаётся открытым

Основной вопрос сейчас — насколько “опечатка” должна распознаваться автоматически.

На данном этапе:
- подсказки реализованы как “поиск по частичному совпадению”
- не реализован более продвинутый fuzzy-match, например по расстоянию Левенштейна

Это важно, потому что:
- частичное совпадение хорошо для `forest` / `fores`
- fuzzy match лучше для реальных опечаток, но его нужно обсуждать отдельно и аккуратно ограничить, чтобы не предлагать слишком много лишних вариантов
