## 1. Цель

Реализовать в MediaTagger автоподсказки для нового тега на основе уже существующих тегов, чтобы пользователь выбирал корректный вариант вместо создания дубликата по опечатке. Сначала подготовлен план по этапам, как требует MediaTagger/docs/prompts/05-task-decomposition.md и правила проекта в MediaTagger/.github/copilot-instructions.md.

## 2. Анализ текущей реализации

### Что уже есть
- В MediaTagger/src/main/GaleryStore.ts есть индекс тегов:
  - `tagIndex: Map<string, Set<string>>`
  - `buildIndexes()`
  - `search(filter)`
  - `getAllTags()`
- В MediaTagger/src/main/index.ts есть IPC-обработчики:
  - `save-tags`
  - `get-all-tags`
- В MediaTagger/src/preload/index.ts значения API доступны в renderer:
  - `getAllTags()`
- В UI:
  - MediaTagger/src/renderer/src/components/Gallery.tsx
  - MediaTagger/src/renderer/src/components/GalleryWithGroup.tsx
  - MediaTagger/src/renderer/src/components/ImageDialog.tsx
  - MediaTagger/src/renderer/src/components/ImageDialogWithGroup.tsx

### Текущее поведение добавления тега
Во всех этих компонентах добавление идёт по паттерну:

- `handleAddTag`
- условие вида `!tags.includes(tagInput.trim())`
- ввод по `Enter` или кнопке

Это означает:
- нет автодополнения;
- нет сравнения с уже существующими тегами по регистру/поиск по совпадению;
- нет проверки на опечатки;
- дубликаты могут появляться как `forest`, `Forest`, `forest ` и т.п., если не нормализовать строки.

### Что уже есть как “поиск/дедупликация”
Существующие механизмы в проекте:

- `GalleryStore.buildIndexes()` строит `tagIndex` по `tag.toLowerCase()`
- `search(filter)` фильтрует изображения по тегам через пересечение наборов
- `getAllTags()` возвращает массив ключей из `tagIndex`
- в UI используется проверка `tags.includes(...)` только по текущему набору тега у изображения/фильтра

То есть:
- логика поиска тегов уже есть в хранилище;
- логика “выбрать из существующих значений” в UI отсутствует;
- нормализация и поиск похожих тегов не реализованы.

## 3. План реализации (минимум 3 этапа)

### Этап 1. Анализ модели тегов и подготовка API для подсказок
- Цель: определить, где в проекте хранится список всех тегов и как его безопасно использовать для подсказок.
- Релевантные файлы:
  - MediaTagger/src/main/GaleryStore.ts
  - MediaTagger/src/main/index.ts
  - MediaTagger/src/preload/index.ts
  - MediaTagger/src/preload/types.ts
- Необходимые изменения:
  - проверить, что `getAllTags()` возвращает нормализованный и пригодный для UI список;
  - при необходимости добавить отдельный метод для “suggestions by prefix / partial match” без ломки текущего API;
  - определить, где лучше хранить нормализацию: в renderer или в main.
- Зависимости:
  - зависит от текущей модели `tagIndex` и структуры хранения тегов.
- Критерий готовности:
  - есть стабильный список существующих тегов из `GalleryStore`;
  - на уровне API ясно, как получить подсказки для вводимой строки.

### Этап 2. Реализация подсказок в UI для ввода тега
- Цель: показать список существующих тегов в поле ввода, когда пользователь начинает печатать.
- Релевантные файлы:
  - MediaTagger/src/renderer/src/components/Gallery.tsx
  - MediaTagger/src/renderer/src/components/GalleryWithGroup.tsx
  - MediaTagger/src/renderer/src/components/ImageDialog.tsx
  - MediaTagger/src/renderer/src/components/ImageDialogWithGroup.tsx
- Необходимые изменения:
  - получить список всех тегов;
  - фильтровать по введённому тексту;
  - показывать варианты выбора в `Autocomplete`/`TextField` или похожем MUI-элементе;
  - при выборе варианта подставлять существующий тег, а не создавать новый.
- Зависимости:
  - нужен результат этапа 1: API/метод для получения подсказок.
- Критерий готовности:
  - при вводе части строки пользователь видит подходящие существующие теги;
  - выбор варианта добавляет существующий тег без дубликата.

### Этап 3. Нормализация и защита от дубликатов
- Цель: исключить повторы, вызванные регистром/пробелами/опечатками.
- Релевантные файлы:
  - MediaTagger/src/main/GaleryStore.ts
  - MediaTagger/src/renderer/src/components/Gallery.tsx
  - MediaTagger/src/renderer/src/components/ImageDialog.tsx
- Необходимые изменения:
  - нормализовать имя тега в одном месте (например, trim + lower-case compare for duplicates);
  - обеспечить сравнение по “схожему” тегу до создания нового;
  - проверять уже существующую коллекцию перед сохранением;
  - сохранить прежнюю UX-логику, но добавить безопасный выбор из существующих значений.
- Зависимости:
  - требует завершённых этапов 1–2.
- Критерий готовности:
  - одинаковые теги не дублируются;
  - ввод похожей строки предлагает корректный существующий тег;
  - пользователь не создаёт новый дубликат по опечатке.

## 4. Риски и способы предотвращения

- Риск: разный регистр и пробелы создадут “дубликаты”.
  - Предотвращение: единая нормализация в `trim()`, lower-case и compare на уровне модели/сервиса.
- Риск: повторный запрос списка тегов слишком дорогой.
  - Предотвращение: использовать уже существующий `tagIndex` и кэшировать список после изменений.
- Риск: UI-выбор добавляет тег, но не обновляет состояние хранения.
  - Предотвращение: использовать тот же путь сохранения, что и у текущих `handleSave` / `saveTags`.
- Риск: логика подсказок должна работать в нескольких местах UI.
  - Предотвращение: вынести общее поведение в маленький reusable helper или переиспользуемый компонент.
