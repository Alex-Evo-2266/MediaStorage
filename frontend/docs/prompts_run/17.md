# Задача: интеграция авторизации и обновление медиатеки

Используй инструкции проекта из `.github/copilot-instructions.md` и существующее техническое задание.

Изучи текущую реализацию `AuthPanel.tsx`, проверку сессии Supabase, основной layout приложения, шапку интерфейса и загрузку списка файлов. Внеси минимальные изменения в существующую архитектуру.

## 1. Авторизация и отображение приложения

- Приведи `AuthPanel.tsx` к существующему дизайну Media Storage: тёмная тема, текущие цвета, отступы, типографика и компоненты Material UI.
- Пока пользователь **не авторизован**, показывай только интерфейс авторизации. Скрывай медиатеку, навигацию, панель пользователя и остальные элементы основного приложения.
- После успешного входа показывай основной интерфейс без перезагрузки страницы.
- Корректно обрабатывай первоначальную проверку сессии: пока Supabase определяет состояние авторизации, показывай индикатор загрузки, а не форму входа или содержимое приложения.
- При выходе из аккаунта скрывай основное приложение и возвращай пользователя к авторизации.
- Используй существующую интеграцию Supabase Auth. Не создавай параллельный механизм авторизации.

## 2. Информация о пользователе и выход

После авторизации перенеси информацию о текущем пользователе и кнопку «Выйти» в **верхний правый угол шапки приложения**, в соответствии с существующим дизайном.

- Используй доступные данные Supabase Auth, например email пользователя.
- Оформи блок в стиле остальных элементов шапки, не перегружая интерфейс.
- На узких экранах блок не должен ломать адаптивную вёрстку.
- Удали старое размещение этих элементов, если оно дублируется.

## 3. Автоматическое обновление списка файлов

Исправь обновление данных медиатеки в следующих ситуациях:

1. **После успешного входа:** автоматически загружай актуальный список файлов для авторизованного пользователя.
2. **После успешной загрузки нового файла:** автоматически обновляй список, чтобы новый файл сразу появился в медиатеке без ручного обновления страницы.

Требования:
- Используй существующий API-слой и текущий механизм получения медиафайлов.
- Обновляй данные только после успешной авторизации или успешного завершения загрузки.
- Организуй обновление через существующее состояние или механизм повторного запроса данных. Не дублируй запросы в нескольких компонентах.
- Предотвращай лишние повторные запросы и гонки запросов, если это возможно в текущей архитектуре.
- При выходе очищай пользовательские данные из состояния, чтобы после смены аккаунта не отображались файлы предыдущего пользователя.
- Сохрани существующие состояния загрузки, обработку ошибок, поиск, фильтрацию и выбор файла.

## 4. Ограничения

- Сначала изучи текущий код и найди фактические точки входа для авторизации, загрузки списка и загрузки файлов.
- Не переписывай проект и не меняй архитектуру без необходимости.
- Не создавай новые API, если нужные методы уже существуют.
- Не изменяй схему базы данных, настройки Supabase или RLS без доказанной необходимости.
- Не используй фиктивную авторизацию и mock-данные вместо реальной интеграции.
- Не добавляй новые зависимости без необходимости.

## 5. Проверка результата

Проверь следующие сценарии вручную по коду и доступным средствам разработки:

- Неавторизованный пользователь видит только авторизацию.
- При восстановлении существующей сессии открывается основное приложение.
- После входа отображаются данные текущего пользователя и актуальный список файлов.
- Новый файл появляется в списке сразу после успешной загрузки.
- После выхода основное приложение скрывается, а данные пользователя очищаются.
- Ошибки авторизации и загрузки данных обрабатываются корректно.
- Шапка и авторизация соответствуют дизайну и остаются адаптивными.

После изменений запусти **только линтинг и production-сборку** из каталога `frontend`, используя существующие команды из `package.json`. Не запускай и не добавляй тесты.

В конце перечисли изменённые файлы, кратко опиши решения и укажи реальные результаты линтинга и сборки. Не заявляй об успешной проверке, если команда завершилась с ошибкой.
