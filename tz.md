# Media Storage — техническое задание на frontend-MVP

## 1. Описание проекта

Media Storage — веб-приложение для просмотра и организации домашней медиатеки, содержащей изображения, видео и аудиофайлы.

На данном этапе разрабатывается только frontend. Данные предоставляются через mock-объекты и хранятся в состоянии React. Реальный сервер, база данных, авторизация и передача файлов на сервер не реализуются.

Интерфейс должен соответствовать подготовленной визуальной концепции: тёмная тема, графитовый фон, тёмно-серые панели, выразительные превью медиафайлов и русскоязычные элементы управления.

## 2. Технологический стек

- React и TypeScript.
- Vite для сборки и запуска проекта.
- Material UI (MUI) для компонентов интерфейса.
- Vitest и React Testing Library для автоматизированного тестирования.
- Git для контроля версий.

## 3. Основные функции

### FR-01. Медиатека

- Отображать список медиафайлов в виде карточек.
- Поддерживать типы файлов: изображения, видео и аудио.
- Фильтровать файлы по типу.
- Искать файлы по названию.
- Показывать пустое состояние, если совпадений нет.

### FR-02. Просмотр файла

- Открывать выбранный файл в модальном окне.
- Показывать доступное превью и информацию о файле: название, тип и размер.
- Поддерживать переход к предыдущему и следующему файлу.
- Закрывать окно кнопкой и клавишей Escape.

### FR-03. Коллекции

- Создавать коллекции с названием.
- Отображать список созданных коллекций.
- Добавлять медиафайлы в коллекцию и удалять их из неё.
- Удалять коллекции с подтверждением действия.
- Хранить изменения в состоянии приложения; сохранение после перезагрузки не является обязательным.

### FR-04. Добавление файлов

- Предоставлять выбор файлов через стандартный диалог браузера.
- Поддерживать drag-and-drop.
- Проверять допустимые типы файлов и ограничения размера.
- Показывать выбранные файлы и состояние имитации загрузки.
- Отображать сообщения об успешном добавлении или ошибке.
- Предоставлять возможность повторить операцию после ошибки.

Добавление файлов выполняется локально, без отправки на сервер. Если для превью используется временный URL браузера, он должен освобождаться при удалении файла или размонтировании соответствующего компонента.

## 4. Требования к интерфейсу

- Все пользовательские надписи должны быть на русском языке.
- Использовать тёмную тему и компоненты Material UI.
- Предусмотреть навигацию по медиатеке и коллекциям.
- Использовать понятные состояния загрузки, ошибки, пустого результата и успешного действия.
- Обеспечить работу на настольных компьютерах, планшетах и смартфонах.
- Не допускать горизонтальной прокрутки страницы на типичных мобильных разрешениях.

## 5. Архитектура frontend

- Разделить интерфейс на переиспользуемые React-компоненты.
- Вынести демонстрационные данные в отдельный модуль.
- Отделить работу с состоянием от представления там, где это упрощает поддержку.
- Не смешивать компоненты интерфейса с будущими запросами к backend.
- Использовать TypeScript-типы для медиафайлов и коллекций.

## 6. Автоматизированные тесты

Необходимо реализовать и успешно выполнить не менее трёх автоматизированных тестов:

1. Поиск и фильтрация: после ввода поискового запроса отображаются только подходящие файлы.
2. Коллекции: пользователь может создать коллекцию и добавить в неё файл.
3. Проверка ошибки: при выборе недопустимого файла отображается сообщение об ошибке, а файл не добавляется в медиатеку.

Тесты должны проверять пользовательское поведение, а не только факт рендеринга компонентов.

## 7. Критерии готовности

- Проект запускается локально без критических ошибок.
- Реализованы четыре основные функции из раздела 3.
- Интерфейс адаптирован для мобильных устройств.
- Все три обязательных автоматизированных теста проходят успешно.
- В проекте нет необработанных ошибок, препятствующих использованию приложения.
- В README описаны установка, запуск и тестирование.
- В `development_report.md` зафиксированы применённые промпты, выявленные ошибки, способы их исправления и результаты тестирования.
- Функции, требующие backend, явно обозначены как не реализованные на текущем этапе.
